To publish your Python script as a standalone CLI tool that anyone can install via pip install <your-package-name> and run directly as a terminal command (e.g., pdfcompress), package it using modern Python packaging standards (pyproject.toml).

Step 1: Organize Your Project Structure
Create a clean directory layout for your project:

Plaintext
pdf-compressor-cli/
├── pyproject.toml
├── README.md
├── LICENSE
└── pdf_compressor/
    ├── __init__.py
    └── cli.py
Move your script logic into pdf_compressor/cli.py.

Step 2: Ensure cli.py Has an Entry Function
Make sure your code in pdf_compressor/cli.py defines a callable entry function (like main()):

Python
# pdf_compressor/cli.py
import argparse
import sys
# ... (rest of your compression functions: compress_pdf, interactive_mode, etc.) ...

def main():
    parser = argparse.ArgumentParser(
        description="Multi-tier PDF Compression CLI Tool",
        epilog="Run without arguments to launch interactive wizard."
    )
    parser.add_argument("input", nargs="?", help="Path to input PDF file")
    parser.add_argument("-l", "--level", type=int, choices=[1, 2, 3], help="Compression tier (1=Light, 2=Medium, 3=Aggressive)")
    parser.add_argument("-o", "--output", help="Path for compressed output PDF")

    args = parser.parse_args()
    # ... handle logic ...

if __name__ == "__main__":
    main()
Leave pdf_compressor/__init__.py empty (or just include __version__ = "0.1.0").

Step 3: Create pyproject.toml
At the root directory (pdf-compressor-cli/), create pyproject.toml. This defines your package metadata, dependencies, and the CLI binary entry point:

Ini, TOML
[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[project]
name = "pdfcompress-cli"  # Must be unique on PyPI
version = "0.1.0"
authors = [
  { name="Shubham", email="youremail@example.com" },
]
description = "A multi-tier interactive and scriptable PDF compression CLI tool"
readme = "README.md"
requires-python = ">=3.8"
classifiers = [
    "Programming Language :: Python :: 3",
    "License :: OSI Approved :: MIT License",
    "Operating System :: OS Independent",
]
dependencies = [
    "pypdf>=4.0.0",
    "pillow>=10.0.0",
]

[project.scripts]
# This registers the terminal command name:
# Command name -> module:function
pdfcompress = "pdf_compressor.cli:main"
Step 4: Test Locally (Editable Install)
Before uploading to the web, install it locally to make sure the terminal command works:

Bash
# Inside the root folder (where pyproject.toml lives):
python3 -m pip install -e .
Verification: Open a new terminal tab and type:

Bash
pdfcompress --help
If the help message displays, your CLI entry point works.

Step 5: Build the Package
Install the standard build tools:

Bash
python3 -m pip install --upgrade build twine
Run the build command to generate source archives and wheels:

Bash
python3 -m build
This creates a dist/ directory containing:

pdfcompress_cli-0.1.0-py3-none-any.whl

pdfcompress_cli-0.1.0.tar.gz

Step 6: Publish to PyPI (Python Package Index)
1. Test on TestPyPI First (Recommended)
Register an account at test.pypi.org.

Go to Account Settings → API tokens and generate a token.

Upload using twine:

Bash
python3 -m twine upload --repository testpypi dist/*
Enter __token__ as the username and your generated API token as the password.

Test installing it in a fresh virtual environment:

Bash
pip install --index-url https://test.pypi.org/simple/ --extra-index-url https://pypi.org/simple/ pdfcompress-cli
2. Publish to Production PyPI
Create an account at pypi.org.

Create an API token under Account Settings → API tokens.

Upload your build:

Bash
python3 -m twine upload dist/*
How Anyone Can Install and Use It
Once uploaded, anyone on Linux, macOS, or Windows can install and use it directly:

Bash
pip install pdfcompress-cli

# Run interactively
pdfcompress

# Or run with CLI flags
pdfcompress sample.pdf -l 2 -o compressed.pdf
